Limitations and Evidence Gaps

This page lists what the project has not yet demonstrated, based on reports/VARDHAN_EVIDENCE_GAPS.md, reports/VARDHAN_FACT_CHECK.md and the forensic audits. These boundaries should be read alongside every result on this site.

1. Hardware Properties Not Measured (Deployment Out of Scope)

Physical deployment on embedded devices is outside the scope of this RF-only research project. All efficiency figures are software estimates or measurements on a development machine; the properties below have not been measured on any target hardware.

Table 1. Hardware properties not measured.
PropertyCurrent statusBoundaryWhat would be needed
Real-time latencyNot measured on embedded hardware11.81 M MACs and 23.63 M FLOPs are graph-derived; no ms/segment figure exists for any embedded device.Export the model and profile it on physical devices.
Memory footprintWeights only (≈ 0.48 MB FP32)Peak activation and scratch SRAM during streaming inference are unknown.Profile peak runtime memory on embedded Linux.
Power consumptionUnmeasuredEnergy cost of continuous 100 MS/s ingestion is unquantified.Measure with a hardware power monitor.
FP16 / INT8 quantisationUnmeasuredAll results are FP32; PTQ / QAT accuracy loss is unknown.Evaluate post-training and quantisation-aware training.

3. Dataset and Protocol Limitations

Table 3. Dataset and protocol limitations.
LimitationContextImplication
Single-site captureAll 454 DroneRF files were recorded in one environment with one pair of USRP-2943R receivers.Cross-location and cross-hardware transfer cannot be established without external datasets.
Phantom band shiftAll 21 Phantom training files are H-band; validation/test Phantom files are L-band.Natural domain shift contributing to 2.55% strict Phantom recall.
Partial 10-fold coverageBecause of GPU time limits, the full 10-fold benchmark was run for FGCS2019DNN, MC1DCNN and VARDHAN-v3 only.DSCNN, CS-CNN and MobileNetV3Small have strict-protocol numbers only.
Sampling disparityHistorical strict baselines: 5 segments/file (365 test segments). VARDHAN-v3 strict: 50 segments/file (3,650).The two strict tables are reported separately and are not a controlled comparison.
Closed-set evaluationOnly 4 known classes are evaluated.Rejection of unknown drones and confidence calibration are untested.
Short segments, single bandVARDHAN models see 2048 samples (20.48 µs) from one 40 MHz receiver.Burst-level and cross-band context available to longer or stitched representations is not used.

4. Documentation Consistency Notes

While building this site, all figures were cross-checked against the raw result files. The following inconsistencies in the project reports were found; this site uses the result files as the authoritative source.

  • VARDHAN-v3 per-class metrics. Some report tables list per-class precision, recall and F1 that do not match the pooled confusion matrix in results/vardhan_v3_per_segment_10fold/. This site shows the values recomputed from that matrix.
  • VARDHAN-v3 parameter breakdown. The component budget quoted in the IEEE report does not sum to 119,806. This site gives a breakdown recomputed from the layer definitions, which sums exactly to 119,806.
  • Class index order. The benchmark scripts use Background, Bebop, AR, Phantom (0–3), whereas src/constants.py and the strict-split scripts use no_drone, ar_drone, bebop_drone, phantom_drone. Every table on this site names classes explicitly.
  • Strict VARDHAN-v3 confusion matrix. A confusion matrix printed in one report does not match the per-class recalls in test_metrics.csv, so it is not reproduced here; only the per-class metrics from the result file are shown.
